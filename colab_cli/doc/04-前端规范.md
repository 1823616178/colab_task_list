# 04 前端规范（Nuxt 3 + Pinia）

## 1. CSS 命名规则

```
container_页面名_功能名_位置名_别名
```

四段全部小写，用下划线连接，**段内不再用下划线**（多词用连写或短横线均可，
但全项目须统一 —— 本项目约定**连写**）。

### 1.1 词表

| 段 | 取值 |
| :--- | :--- |
| **页面名** | `dash` `task` `workflow` `session` `user` `login` |
| **功能名** | `list` `detail` `create` `filter` `auth` `stat` `reconcile` |
| **位置名** | `header` `toolbar` `sidebar` `body` `footer` `card` `panel` `row` `cell` `modal` `form` `timeline` |
| **别名** | 具体语义，自由但需可读：`gpu` `submit` `status` `title` `orphan` … |

### 1.2 实例

```html
<!-- 任务提交页 -->
<div class="container_task_create_form_root">
  <div class="container_task_create_toolbar_workflow"></div>
  <div class="container_task_create_toolbar_gpu"></div>
  <label class="container_task_create_form_mountdrive"></label>
  <button class="container_task_create_footer_submit"></button>
</div>

<!-- 任务详情页 -->
<section class="container_task_detail_timeline_phase"></section>
<section class="container_task_detail_panel_metrics"></section>
<pre    class="container_task_detail_panel_logscroll"></pre>
<a      class="container_task_detail_footer_download"></a>

<!-- 会话页：孤儿告警 -->
<div class="container_session_list_card_orphan"></div>
<button class="container_session_list_cell_stop"></button>

<!-- 登录页 -->
<form class="container_login_auth_form_root"></form>
```

### 1.3 两条硬性约定

**① 不要用 `<style scoped>`。**
本命名规则已保证全局唯一。再开 `scoped`，Vue 会额外注入 `data-v-xxxxxxx`
属性选择器，调试时两套定位机制打架，且选择器权重变得难以预测。
统一用 `<style>` + 本规则约束作用域。

**② 状态用 `data-*` 属性表达，不要拼第五段。**

```html
<!-- ✅ -->
<tr class="container_task_list_row_item" data-status="recoverable">

<!-- ❌ 会导致类名爆炸 -->
<tr class="container_task_list_row_item_recoverable">
```

```css
.container_task_list_row_item[data-status="recoverable"] { … }
```

### 1.4 校验

加一条 ESLint / stylelint 规则守住格式，避免半年后规则失效：

```
^container_(dash|task|workflow|session|user|login)_[a-z]+_[a-z]+_[a-z]+$
```

## 2. 页面清单

| 路由 | 页面 | 权限 | 要点 |
| :--- | :--- | :--- | :--- |
| `/login` | 登录 | 公开 | 唯一免 JWT 页 |
| `/` | 总览 | viewer+ | 运行中任务卡片、会话健康、**孤儿告警条** |
| `/tasks` | 任务列表 | viewer+ | 状态筛选，`recoverable` 置顶高亮 |

| `/tasks/:id` | 任务详情 | viewer+ | 见 §2.2 |

| `/admin/users` | 用户 | admin | |

### 2.1 提交任务页

表单字段与 `run.py` argparse 一一对应，但**要做前置校验**，把
`validate_workflow_accelerator()` (`run.py:1105`) 的规则搬到前端：

- 选中工作流后，`supportedAccelerators` 之外的加速器**置灰**，
  hover 显示该工作流的 `acceleratorNote`
  （例：MiniMax H3 选 TPU 时提示「ComfyUI 节点使用 CUDA/PyTorch」）
- 勾选「复用会话」时，加速器选择器隐藏（由现有 VM 决定），
  并实时拉 `GET /api/sessions` 确认目标会话 `status !== 'busy'`
- 展示该工作流的模型总体积（`totalModelBytes`）与预估首次耗时，
  提交按钮旁提示「首次运行需下载 ~39 GB」
- 按工作流 `editableFields` 动态渲染文本或下拉参数并从当前 `api.json` 预填；
  只把发生变化的值作为 `workflow_overrides` 提交，覆盖仅作用于任务快照
- 显示当前 API 工作流引用的输入图片，MiniMax H3 按连线标注首帧/尾帧；
  图片经鉴权接口读取，文件缺失时提示先上传

### 2.2 任务详情页

三个区域，**数据源不同，刷新频率不同**：

| 区域 | 数据源 | 频率 |
| :--- | :--- | :--- |
| 阶段时间线 | `task_events` 表（历史）+ SSE `start/ok/warn/error` | 低 |
| 资源图表 | SSE `metrics.sample` | 2 秒 |
| 实时日志 | SSE `log.line` | 高频 |

日志面板要求：

- 虚拟滚动，只渲染可视行（长任务几万行）
- 「跟随底部」开关，用户上滚时自动关闭
- `progress` 类的 `\r` 刷新行**就地覆盖**，不追加新行

终态时按 `status` 切换底部动作区：
`succeeded` → 下载 ZIP；`recoverable` → **重试下载（醒目按钮）**；
`failed` → 下载 run.log。

## 3. Pinia Store 划分

```
stores/
├── auth.ts        用户、accessToken、登录/刷新/登出
├── task.ts        任务列表、分页、筛选、提交
├── taskStream.ts  单任务 SSE：事件、日志、指标
├── workflow.ts    工作流列表与同步
├── session.ts     会话列表、对账结果、孤儿告警
└── ui.ts          toast、全局 loading、主题
```

### 3.1 auth.ts

```ts
// accessToken 只放内存，不进 localStorage / Cookie
const accessToken = ref<string | null>(null)
```

refresh token 是 HttpOnly Cookie，前端**碰不到也不该碰**。
封装一个 `$apiFetch`：遇 401 → 自动打 `/api/auth/refresh` → 重放原请求；
刷新也失败 → 清 store 跳 `/login`。**并发 401 要合流成一次刷新**，
否则会触发后端的「token 重用 → 撤销全部」保护。

### 3.2 taskStream.ts（性能关键）

`metrics.sample` 每 2 秒、`log.line` 高频 —— 直接塞进 `ref` 数组会让整页
反复重渲染。

```ts
// 日志：shallowRef + 环形缓冲，上限 2000 行
const logLines = shallowRef<string[]>([])

// 指标：定长环形缓冲，只保留最近 150 个采样点（约 5 分钟）
const metrics = shallowRef<MetricSample[]>([])

// 时间线：低频，可以用普通 ref（深响应无所谓）
const phases = ref<PhaseNode[]>([])
```

连接管理：

- 进页面 `onMounted` 开 `EventSource`，`onUnmounted` 必须 `close()`
- 断线用 `seq` 续订：`GET /api/tasks/:id/events?from_seq=<lastSeq>`
- 指数退避重连（1s → 2s → 4s → 上限 30s）
- 任务已是终态 → 不建流，直接拉历史事件 + `run.log`

> 注意：浏览器断开**不影响** Nitro↔Runner 的订阅，
> 见 [02 §3.3](./02-接口契约.md)。前端可以放心关流。

### 3.3 session.ts

孤儿告警要做成**全局横幅**（在 `app.vue` 层），不只在 `/sessions` 页 ——
孤儿 VM 在持续烧计算单元，用户在哪个页面都得看见。

```ts
const orphans = computed(() =>
  sessions.value.filter(s => s.reachable && !s.expectedAlive && !s.hasRunningTask))
```

## 4. 其他约定

- **时间**：库内与接口全部 UTC，展示时转本地时区。
  `task_id` 前缀本身就是 UTC 时间戳，不要拿它当本地时间显示。
- **体积**：模型/输出用 GiB/MiB（与 `remote_workflow.py` 的
  `size_bytes` 口径一致），不要用 GB/MB 混着写。
- **文案**：沿用现有中文术语 —— 「会话」「工作流」「加速器」
  「复用 VM」「保留 VM」，与 `start.sh` 菜单保持一致，降低迁移认知成本。
- **可访问性**：加速器置灰项要用 `aria-disabled` + `title`，
  不能只靠颜色区分。
- **标签页标题**：每个页面用 `useHead({ title: '…' })` 只声明自己那一段，
  `· Colab 控制台` 后缀由 `app.vue` 的 `titleTemplate` 统一拼接
  （写成函数以便没设 title 的页面回落成纯站名；`nuxt.config` 里不支持函数）。
  标题文案与 §2 页面清单、导航项保持一致；动态路由用函数式 title，
  数据没回来时先用 `slug` / `task_id` 占位。
