# 07 UI 风格优化计划（P6）

P0–P5 功能已全部收口（[05 §P5](./05-任务清单.md)），页面能用但**没有设计系统**：
15 个 `.vue` 文件里手写了约 1750 行 CSS，颜色靠记忆复制粘贴。
本文是一次**纯样式层**的重构计划 —— 不改模板结构、不改 store、不改接口。

---

## 1. 现状审计（数字都是实测）

| 指标 | 现状 | 问题 |
| :--- | :--- | :--- |
| 硬编码颜色 | **36 个不同 hex**，散落 15 个文件 | 改主色要全局搜替换 36 次 |
| CSS 变量 | **0 个** | 无 token 层 |
| `:hover` | **0 处** | 所有按钮/链接/行都是死的 |
| `:focus` / `outline` | **0 处** | 键盘不可见焦点，违反 [04 §4 可访问性](./04-前端规范.md) |
| `transition` / `animation` | **0 处** | 状态切换硬跳 |
| `@media` | **1 处** | 1200px 定宽表格，窄屏直接横向溢出 |
| `prefers-color-scheme` | **0 处** | 无暗色 |
| 容器宽度 | `960` / `1200` / `640` 三种 | 页面间跳宽 |
| `border-radius` | `4px`×39、`8px`×32、`6px`×1 | 6px 是笔误 |
| `font-size` | 11/12/13/14/15/16/17/20/22px 九档 | 无字阶 |
| monospace 字体栈 | 4 个文件各写各的 | LogViewer 与 sessions 不一致 |

### 1.1 重复最严重的四类

1. **按钮**：`padding: 6px 14px; background:#fff; border:1px solid #c9cdd4; border-radius:4px; cursor:pointer`
   这一组在 9 个文件里重复；危险按钮（`#d03050`）重复 5 次；主按钮（`#165dff`）重复 3 次。
2. **表格**：`border-collapse` + 表头 `#fafbfc` + 行分隔 `#f0f0f0` 在 5 个页面各抄一遍
   （`tasks/index`、`sessions/index`、`history`、`workflows/index`、`admin/users`）。
3. **卡片**：`background:#fff; border:1px solid #e5e6eb; border-radius:8px` 出现 20+ 次。
4. **状态色**：`data-status` 的配色映射在 6 个文件里各写一份
   （`tasks/index` 8 条、`sessions/index` 7 条、`tasks/[id]` 6 条、`history` 5 条、
   `TaskTimeline` 5 条、`index` 3 条），且**已经不一致** ——
   `recoverable` 在 `index.vue` 是 `#fff7e8`，在 `tasks/index.vue` 是 `#fff3e0`。

> 状态色不一致是这次重构最有价值的修复点：`recoverable`（可恢复，钱还在烧）
> 是整个产品最需要一眼认出的状态，它现在有两个底色。

## 2. 目标与非目标

**目标**

- 一处改主色/圆角/间距，全站生效
- 所有可交互元素有 hover / focus-visible / disabled 三态
- 状态语义（`running` / `succeeded` / `failed` / `recoverable` / `orphaned`）全站唯一定义
- 窄屏（含平板竖屏）不横向溢出
- 视觉方向：**克制的现代控制台** —— 保留现有 Arco 蓝 `#165dff` 作主色，
  补上层次（阴影/边框分级）、字阶、等宽数字，去掉"纯白盒子堆叠"的扁平感

**非目标（本次不做）**

- 不引入 UI 组件库（Arco/Element/Naive）—— 会和现有命名规则、SSR、包体积打架
- 不引入 Tailwind —— 与 [04 §1](./04-前端规范.md) 的 `container_*` 规则正面冲突
- 不改任何 `<template>` 的结构语义（只允许增删 class/`data-*`）
- 不动 `LogViewer` 的虚拟滚动、`MetricsChart` 的绘制逻辑

---

## 3. 阻塞决策：命名规则要不要开口子

现有 stylelint 规则（`stylelint.config.mjs`）：

```
^container_(dash|task|workflow|session|user|login)_[a-z]+_[a-z]+_[a-z]+$
```

页面段是**枚举死的**，所以**写不出跨页共享的 class**。这是重复的根因，
不解决它，第 4 节的收敛只能做一半。三个选项：

| 方案 | 做法 | 代价 |
| :--- | :--- | :--- |
| **A（推荐）** | 只加 CSS 自定义属性 + 无 class 的元素级基础样式（`button`/`input`/`table`/`a`），命名规则一字不改 | 覆盖约 70% 重复；特例按钮仍需页面内写 |
| B | 规则加一个 `ui` 页面段，允许 `container_ui_btn_base_primary` 这类共享类 | 要改 stylelint 正则 + [04 §1.1](./04-前端规范.md) 词表；能覆盖 ~95% |
| C | 保持规则，靠 Vue 组件封装（`<UiButton>`）而非共享 class | 要动模板，越出"纯样式层"边界 |

**建议 A 起步**：自定义属性不是 class 选择器，不受正则约束；
元素选择器（`button { … }`）根本没有 class。两者叠加就能吃掉大部分重复，
且**零规则变更、零模板变更**，风险最低。若做完阶段 3 仍觉得特例太多，再升级到 B。

以下计划按方案 A 展开，并在阶段 3 结束时留一个复盘点。

## 4. 分阶段实施

### 阶段 1 · Token 层（`assets/css/main.css`）

新增 `:root` 变量，**一次性覆盖审计出的 36 个 hex**。命名按语义而非色值：

```css
:root {
  /* 主色 */
  --c-brand:        #165dff;
  --c-brand-hover:  #4080ff;
  --c-brand-active: #0e42d2;
  --c-brand-bg:     #f0f6ff;

  /* 中性（沿用现有 Arco 灰阶，只是给名字） */
  --c-text:         #1d2129;   /* 正文，注意现状 #1f2329/#1d2129 混用，统一到 #1d2129 */
  --c-text-sub:     #4e5969;
  --c-text-weak:    #86909c;
  --c-border:       #e5e6eb;   /* 卡片/分隔 */
  --c-border-strong:#c9cdd4;   /* 输入框/次级按钮 */
  --c-bg:           #f5f6f7;   /* 页底 */
  --c-surface:      #fff;      /* 卡片面 */
  --c-surface-sub:  #fafbfc;   /* 表头 */

  /* 状态语义：全站唯一定义，替换 6 个文件里各写一份的映射 */
  --c-running:      #165dff;  --c-running-bg:     #f0f6ff;
  --c-success:      #16803c;  --c-success-bg:     #e8f7ed;
  --c-danger:       #d03050;  --c-danger-bg:      #ffece8;
  --c-warn:         #ff7d00;  --c-warn-bg:        #fff3e0;  /* recoverable 统一用这套 */
  --c-warn-text:    #b25000;

  /* 字阶：九档收敛到六档 */
  --fs-xs: 12px; --fs-sm: 13px; --fs-md: 14px;
  --fs-lg: 16px; --fs-xl: 20px; --fs-2xl: 24px;

  /* 间距：4 的倍数 */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-6: 24px; --sp-8: 32px;

  /* 圆角：两档（4px 控件 / 8px 容器），干掉那个 6px */
  --r-sm: 4px; --r-md: 8px;

  /* 阴影：现状只有 toast 有一条，补成三档 */
  --sh-1: 0 1px 2px rgb(0 0 0 / 4%);
  --sh-2: 0 2px 8px rgb(0 0 0 / 8%);
  --sh-3: 0 4px 16px rgb(0 0 0 / 12%);

  /* 动效 */
  --t-fast: 120ms ease;

  /* 字体栈：补 system-ui 前缀 + 统一 mono（现在 4 个文件各写各的） */
  --ff-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;

  /* 布局：三种容器宽度收敛成两种 */
  --w-page: 1200px;   /* 列表/详情页 */
  --w-form: 640px;    /* 表单页（tasks/new、frames） */
}
```

**验收**：文件本身可独立提交，此时页面外观零变化。

### 阶段 2 · 元素级基础样式（仍在 `main.css`）

不写 class，直接给裸元素兜底，吃掉第 1.1 节的重复：

- `button` —— 默认次级按钮外观 + `:hover` / `:focus-visible` / `:disabled` 三态
  （现状 `:disabled` 各页面重复写了 `opacity: .5/.6` 两种值，一并统一）
- `input, select, textarea` —— 边框、圆角、`:focus` 环（`--c-brand` + 2px outline offset）
- `table / th / td` —— `border-collapse`、表头底色、行分隔线、`tbody tr:hover`
- `a` —— 主色、`text-decoration` 策略
- `code, pre` —— `--ff-mono`
- 数字/时间列 —— `font-variant-numeric: tabular-nums`（任务列表、耗时、体积全受益）
- 焦点基线 —— `:focus-visible { outline: 2px solid var(--c-brand); outline-offset: 2px }`，
  这是当前**从 0 到 1** 的可访问性修复

**验收**：`pnpm lint` 通过（stylelint 对元素选择器无意见）；肉眼过一遍所有页面，
只允许"变好看"，不允许布局位移。

> 若明显 > 20 处，停下来重新评估第 3 节的方案 B。

### 阶段 4 · 交互与动效

- 卡片/行 hover：`--sh-1` → `--sh-2`，`transition: box-shadow var(--t-fast)`
- 按钮按下态（`:active`）位移 0，只变色 —— 控制台工具不做花哨反馈
- toast 进出场：`<TransitionGroup>` + 位移淡入（app.vue 已有容器，只加过渡）
- 长任务运行中状态加一个**极克制**的呼吸点（`running` 圆点 1.5s opacity 循环）
- 全局 `@media (prefers-reduced-motion: reduce)` 关闭所有动效

### 阶段 5 · 响应式

当前只有 1 条 `@media`，5 个 1200px 定宽表格页在窄屏直接横向溢出。

- 断点定两个：`768px`（平板/窄屏）、`1280px`（宽屏上限）
- 表格页：窄屏下给 `overflow-x: auto` 包裹 + 关键列（任务名/状态）`position: sticky` 左固定
- `app.vue` 导航：窄屏改为可横向滚动的 tab 条（不做汉堡菜单，导航项最多 7 个）
- `tasks/new.vue` 表单：窄屏单列（现在是隐式两列 flex）

### 阶段 6 · 暗色模式（可选，独立决策）

阶段 1 的 token 若一次做对，暗色只是重定义一遍 `:root` 变量：

```css
@media (prefers-color-scheme: dark) { :root { --c-surface: #1d1f23; … } }
```

但需要人工核对 5 组状态色在深底上的对比度（≥ 4.5:1），
以及 `MetricsChart` 的绘制色。**建议阶段 1–5 落地稳定后再单独排期**，
不要和主线混在一起做。

### 8.3 三个值得记下的坑

**① `button:hover:not(:disabled)` 的特异度是 (0,2,1)，会压过页面的
`.container_xxx:hover` (0,2,0)。** 所以基线的 hover **不能**写死品牌色 ——
否则页面上那些红底白字的「停止 / 删除」按钮 hover 时会被强行改蓝。
最终基线 hover 用 `filter: brightness()`，对描边按钮和实心按钮同时成立。

**② 行 hover 必须落在 `<tr>` 而不是 `<td>`。** 写成 `tbody tr:hover td`
（特异度 0,0,3）会盖住页面里 `[data-status='recoverable']` 的琥珀底色 ——
那恰恰是全站最不能丢的状态标记。改成 `tbody tr:hover` (0,0,2) 后，
页面的 (0,2,0) 稳稳压住它。

**③ 长得像按钮的 `<a>` 必须显式写 `:hover`。** 基线 `a:hover` (0,1,1) 会盖过
类选择器 (0,1,0)。命中两处：孤儿告警条的白色药丸按钮、任务详情页的
Drive 授权按钮，不写就会在红底/琥珀底上变成蓝字。

### 8.4 与原计划的偏差

- **静态卡片没有加 hover 抬升**（第 4 节阶段 4 原本列了）。卡片本身不可点，
  给不可点的东西加 hover 反馈是噪声。hover 只保留在真正可交互的表格行上。
- **动了三处 `<template>`**，超出「只改 class/`data-*`」的自我约束，均为样式所必需：
  - `app.vue` 的 toast 容器换成 `<TransitionGroup tag="div">`（不增加 DOM 层级）
  - 4 个列表页的表格套了 `*_table_scroll` 滚动容器（沿用 `history.vue` 已有的命名）
  - Vue 过渡类名用 `enter-active-class` 等 prop 显式指定，因为默认生成的
    `xxx-enter-active` 不符合命名规则、会被 stylelint 拦下
