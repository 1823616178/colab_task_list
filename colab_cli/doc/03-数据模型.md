# 03 数据模型（TypeORM + MySQL）

## 1. 铁律：写库归属

> **只有 Nuxt/TypeORM 写 MySQL。Python Runner 一个字都不许写。**

否则会出现 TypeORM 与 SQLAlchemy 两套 schema 定义，迁移时必然打架。

Runner 只在本地维护 `runner_state.json`，记录在飞任务，用于**自身崩溃后
的重启对账**，不是持久化真相：

```jsonc
{ "tasks": { "20260822-103102-c89fc79c": {
      "session": "comfyui-h3", "pid": 0, "started_at": "...",
      "last_seq": 137, "phase": "workflow.exec" } } }
```

配置约定：

```ts
// 生产禁用 synchronize，一律走 migration
synchronize: false,
migrationsRun: true,
charset: 'utf8mb4',          // 工作流名/文件名含中文
timezone: 'Z',               // 全库 UTC，与 task_id 的 UTC 时间戳一致
```

## 2. 认证相关

### User

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `int` PK auto | |
| `username` | `varchar(64)` unique | |
| `passwordHash` | `varchar(255)` | argon2id（优于 bcrypt）|
| `role` | `enum('admin','operator','viewer')` | 见下 |
| `isActive` | `boolean` default true | 停用而非删除 |
| `mustChangePassword` | `boolean` default false | 首次登录强制改密；007 seed 与 admin 新建/重置密码的用户置 true |
| `createdAt` / `lastLoginAt` | `datetime` | |

角色权限：

| role | 权限 |
| :--- | :--- |
| `admin` | 全部 + 用户管理 |
| `operator` | 提交/取消任务、停止会话、管理工作流 |
| `viewer` | 只读任务与会话 |

> 提交任务 = 花计算单元，所以 `viewer` 必须挡在 `POST /api/tasks` 之外。

### RefreshToken

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `char(36)` PK | uuid，即 JWT 的 `jti` |
| `userId` | FK → User | `onDelete: CASCADE` |
| `tokenHash` | `char(64)` | SHA-256，**不存明文** |
| `expiresAt` | `datetime` | 7 天 |
| `revokedAt` | `datetime` null | 登出/轮换时置位 |
| `userAgent` / `ip` | `varchar` | 审计 |

索引：`(userId, revokedAt)`、`(expiresAt)`（清理用）。

刷新时**轮换**：旧 token 立即 `revokedAt`，签发新的。若收到已撤销的
token → 判定为泄露，撤销该用户全部 refresh token。

## 3. 业务实体

### WorkflowConfig

`workflows/*.json` 在库中的镜像，供 `Task` 外键引用与列表展示。
**文件仍是真相**，通过 `POST /api/workflows/sync` 单向同步。

| 字段 | 类型 | 来源 |
| :--- | :--- | :--- |
| `id` | `int` PK auto | |
| `slug` | `varchar(128)` unique | 文件名去扩展名，如 `minimax_h3` |
| `name` | `varchar(255)` | 配置 `name`，如「MiniMax H3 首帧视频」 |
| `configPath` | `varchar(512)` | 相对仓库根 |
| `apiJsonPath` | `varchar(512)` | 解析 `api_json` 后的实际路径 |
| `supportedAccelerators` | `json` | `["gpu"]` |
| `acceleratorNote` | `text` null | 不兼容时的提示文案 |
| `inputFields` | `json` | `[{class_type, field, local_dir}]` |
| `editableFields` | `json` | 任务页可编辑的 API 节点输入白名单 |
| `comfyFlags` | `json` | |
| `models` | `json` | 原样存，含 `size_bytes` |
| `totalModelBytes` | `bigint` | 派生，用于 UI 预估耗时 |
| `syncedAt` | `datetime` | |

### Session

**这张表是防孤儿 VM 的核心**（见 [01 §5 R2](./01-架构设计.md)）。

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `int` PK auto | |
| `name` | `varchar(128)` unique | 如 `comfyui-h3` |
| `accelerator` | `enum('gpu','tpu','cpu')` null | 由 `Variant:` 解析 |
| `variant` | `varchar(32)` null | `A100` / `L4` / `TPU v6e-1` |
| `endpoint` | `varchar(255)` null | 用于名称映射丢失时按 endpoint 停止 |
| `status` | `enum('idle','busy','unreachable','stopped')` | |
| `expectedAlive` | `boolean` | 我们**认为**它该活着 |
| `createdAt` / `lastSeenAt` / `stoppedAt` | `datetime` | |
| `reconciledAt` | `datetime` null | 上次对账时间 |

**对账规则**（Nitro 启动 + 每 5 分钟）：

```
拉 GET /sessions，与本表 join：
  实际活 & expectedAlive=false & 无 running task  → ⚠️ 孤儿，告警 + 一键停止
  实际死 & expectedAlive=true                     → 标记 unreachable，关联任务转 orphaned
  实际活 & 有 running task                        → 正常，更新 lastSeenAt
```

| `modelMode` | `varchar(16)` default `auto` | 模型获取方式：`auto` / `download` / `symlink` / `copy` |
| `timeout` | `double` default 86400 | |

| `currentPhase` | `varchar(32)` null | 最后一个 `start` 事件的 phase |

| `sessionKept` | `boolean` default false | 失败保护是否触发 |
| `transportMode` | `enum('native','cli','dry_run')` null | 实际使用的通道，排错用 |
| `errorCode` / `errorMessage` | `varchar` / `text` null | |
| `createdByUserId` | FK → User | `onDelete: SET NULL` |

索引：`(status, queuedAt)`、`(sessionName, status)`、`(workflowConfigId)`。

`(sessionName, status)` 上加**部分唯一约束**（MySQL 无原生支持，用应用层
+ 一个 `activeSessionKey` 生成列实现）：同一 session 只允许一个非终态任务。

### TaskEvent

**只存里程碑，不存日志行。** 几十行/任务，不是几万行。
过滤规则见 [02 §1.1](./02-接口契约.md)。

| 字段 | 类型 |
| :--- | :--- |
| `id` | `bigint` PK auto |
| `taskId` | FK → Task `onDelete: CASCADE` |
| `seq` | `int` |
| `ts` | `datetime(3)` |
| `phase` | `varchar(32)` |
| `status` | `enum('start','ok','warn','error')` |
| `message` | `text` |
| `data` | `json` null |

唯一索引 `(taskId, seq)` —— 兼作 SSE 重放去重。

> **禁止**写入 `phase IN ('metrics.sample','log.line')` 或
> `status='progress'` 的事件。在 Repository 层加断言。

### ModelCache

Google Drive 39 GB 模型缓存的可见性（现在只能靠日志猜）。

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | `int` PK auto | |
| `repo` | `varchar(255)` | `Comfy-Org/MiniMax-H3` |
| `filename` | `varchar(512)` | 仓库内路径 |
| `comfyDir` | `varchar(64)` | `diffusion_models` / `vae` / `loras` … |
| `cachePath` | `varchar(512)` | Drive 内相对路径 |
| `sizeBytes` | `bigint` | |
| `present` | `boolean` | 上次任务中是否命中 |
| `lastSource` | `enum('drive_cache','huggingface','vm_local')` | |
| `lastVerifiedAt` | `datetime` | |

唯一索引 `(repo, filename)`。由 `model.prepare` 事件的 `data` 更新。

> 特例：`Wan2.2-big.safetensors` 无法确认来源，必须手工放到
> `MyDrive/code/backup/models/loras/`。UI 应对 `present=false` 且无 `repo`
> 的条目给出明确的手工放置指引。

## 4. Task 状态机

```
                  ┌──────────┐
                  │  queued  │
                  └────┬─────┘
                       │ Runner 接受
                  ┌────▼─────┐
        ┌─────────┤ running  ├─────────┐
        │         └────┬─────┘         │
        │              │               │
   ┌────▼────┐   ┌─────▼─────┐   ┌─────▼──────┐
   │succeeded│   │  failed   │   │  canceled  │
   └─────────┘   └─────┬─────┘   └────────────┘
                       │ 会话被保留、结果可能还在远端
                 ┌─────▼──────────┐
                 │ recoverable    │──redownload──> succeeded
                 └────────────────┘

   任意态 + 会话对账发现 VM 已消失 ──> orphaned
```

| status | 含义 | UI 动作 |
| :--- | :--- | :--- |
| `queued` | 已建行，等 session 空闲 | 取消 |
| `running` | Runner 执行中 | 看实时流、取消 |
| `succeeded` | 结果已落盘并校验 | 下载 ZIP |
| `failed` | 失败且无可恢复产物 | 看日志 |
| `recoverable` | **失败但 VM 保留、远端可能有成品** | **重试下载**（高亮）|
| `canceled` | 用户取消 | |
| `orphaned` | 对账发现 VM 已消失，状态不可知 | 看日志 |

`recoverable` 直接对应 `run.py:1330` 的失败保护分支：
`workflow_completed=True` 但 `output_retrieved=False` 时会保留 VM 并提示
`--download-only`。**这个状态必须在 UI 上非常醒目 —— 它意味着一次几十分钟
的 A100 推理成果还在远端，且 VM 正在持续计费。**
