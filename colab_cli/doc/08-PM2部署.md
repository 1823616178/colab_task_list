# 08 PM2 部署与日志

用 PM2 常驻 [01 §6](./01-架构设计.md) 里的两个进程。配置在仓库根的
`ecosystem.config.cjs`，日志落 `colab_cli/logs/`。

```
colab-console   Nuxt 生产服务    0.0.0.0:54471   ← 浏览器
colab-runner    Python 作业服务  127.0.0.1:8765  ← 只有 console 打得到
```

> 已有的 `colab_runner/colab-runner.service`（systemd）仍然可用，
> **但两者只能选一个** —— 同时拉起会有两个 Runner 抢 8765 端口和 CLI 状态文件。
> 选 PM2 就先 `sudo systemctl disable --now colab-runner`。

## 1. 首次部署

```bash
# 0) 前置：Node ≥ 20（--env-file-if-exists 需要）、Python 环境、MySQL 可达
npm install -g pm2

# 1) 配置。密钥只有 web/.env 一处真相，两个进程都从它取
cd colab_cli/web
cp .env.example .env && vi .env      # 见 web/README.md 的环境变量表

# 2) console 必须先构建，PM2 跑的是 .output/ 里的产物，不是源码
npm ci && npm run build

# 3) 起服务
cd ..
pm2 start ecosystem.config.cjs
pm2 status
```

⚠️ **`nuxt build` 会把构建时的 `.env` 明文快照进 `.output/`**
（见 `web/README.md`）。所以 `.output/` 和 `logs/` 一样，不是可以随便分发的东西。

## 2. 日常命令

```bash
pm2 status                       # 两个进程的状态/重启次数/内存
pm2 logs                         # 跟随全部日志
pm2 logs colab-runner --lines 200
pm2 restart colab-console        # 改了前端/后端代码：先 npm run build 再 restart
pm2 reload  colab-console        # ⚠️ 无效：reload 是 cluster 模式的能力，这里等同 restart
pm2 stop    colab-runner
pm2 describe colab-console       # 看实际生效的 cwd / node_args / 日志路径
```

**改完代码的正确顺序**：

```bash
cd colab_cli/web && npm run build && pm2 restart colab-console
```

只 `pm2 restart` 不 `build`，跑的还是旧产物 —— 这是最容易踩的一脚。

## 3. 开机自启

```bash
pm2 start ecosystem.config.cjs
pm2 save                         # 固化当前进程列表到 ~/.pm2/dump.pm2
pm2 startup                      # 按它打印的那行 sudo 命令执行一次
```

`pm2 save` 忘了执行的话，重启机器后 PM2 会起来但进程列表是空的。

## 4. 日志

### 4.1 落盘位置

| 文件 | 内容 |
| :--- | :--- |
| `logs/console-out.log` / `console-error.log` | Nitro 的 stdout/stderr：HTTP 错误、migration、SSE 订阅与补拉、定时清理 |
| `logs/runner-out.log` / `runner-error.log` | Runner 的 stdout/stderr：uvicorn 访问日志、transport 降级告警、会话对账 |

带 `YYYY-MM-DD HH:mm:ss Z` 时间戳前缀（`log_date_format`），否则事后没法把
两个进程的事件对齐。`logs/` 已 gitignore（只留 `README.md`）。

### 4.2 这里**没有**任务日志

单个任务的完整远端输出在 `colab_output/<task_id>/run.log`，由 Runner 直接写，
**64 MiB 硬上限并自动滚成 `run.log.1`**（doc/02 §2.6）。浏览器上的实时日志、
`GET /api/tasks/:id/log` 下载的也都是它。

PM2 日志只是服务本身的 stdout/stderr。排查「某个任务为什么失败」看 `run.log`；
排查「服务为什么起不来 / 为什么 503」才看这里。

产物目录另有保留期清理（默认 14 天，`NUXT_OUTPUT_RETENTION_DAYS`，
`plugins/04.output-cleanup.ts`），与 PM2 日志轮转是两回事，互不覆盖。

### 4.3 轮转（必须单独装）

PM2 自己**不轮转**日志，跑几个月能涨到几个 G。装模块：

```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 50M          # 单文件上限
pm2 set pm2-logrotate:retain 14             # 保留 14 份
pm2 set pm2-logrotate:compress true         # 旧的 gzip
pm2 set pm2-logrotate:rotateInterval '0 0 * * *'   # 每天 0 点也切一次
pm2 set pm2-logrotate:dateFormat 'YYYY-MM-DD_HH-mm-ss'
```

查当前配置：`pm2 conf pm2-logrotate`。

清空（不轮转，直接倒掉）：`pm2 flush` 或 `pm2 flush colab-runner`。

## 5. 配置里几个不能改的地方

### 5.1 console 必须 `fork` + 单实例

`ecosystem.config.cjs` 写死了 `exec_mode: 'fork'` / `instances: 1`，
**不要改成 cluster 或多实例**：

- SSE 订阅管理器把「每任务一条 Nitro→Runner 长连接」存在**进程内存**里
  （`server/services/taskSubscription.ts`），多实例 = 重复订阅、重复回写 `tasks` 行；
- 启动补拉 `plugins/03.task-recovery.ts` 会被每个实例各跑一遍。

要扛并发就在前面加 Nginx，不要加 console 实例。

### 5.2 `watch` 必须关

`colab_output/` 就在仓库里，产物一落盘就会触发重启 —— 而重启 runner 的代价见下条。

### 5.3 重启 runner 会弄丢在途任务

console 有启动补拉，能扛自己的重启（Nitro 宕机窗口内完结的任务，重启后会补齐）。
**Runner 没有对等机制**：任务可能跑几小时，进程一没，在途任务被标 `orphaned`，
而那台 Colab VM **还在计费**。

所以：

- 别顺手 `pm2 restart all`，先看 `/tasks` 有没有 running 的；
- `kill_timeout` 给到 30s，让 Runner 有机会把手里的 VM 收干净；
- 真重启完了，去 `/sessions` 页跑一次对账，把孤儿 VM 停掉（doc/04 §3.3）。

### 5.4 runner 走 node 壳而不是直接调 python

`script: 'scripts/start-runner.mjs'` 而不是 `python3 -m colab_runner`，
是为了复用脚本里已有的环境变量映射（`NUXT_RUNNER_TOKEN` → `COLAB_RUNNER_TOKEN`、
`NUXT_RUNNER_OUTPUT_DIR` → `COLAB_OUTPUT_DIR`），让密钥只有 `web/.env` 一处真相，
且 dev（`npm run runner`）与生产（PM2）走同一条代码路径。

代价是多一个 node 壳进程（约 40MB）。壳里已经做了 **SIGINT/SIGTERM/SIGHUP 转发**
（`start-runner.mjs`）—— 没有它，`pm2 stop` 只杀得掉壳，python 会变成孤儿进程
继续攥着一台在计费的 VM。

## 6. 排查

| 症状 | 先看哪里 |
| :--- | :--- |
| `pm2 status` 里 restart 次数狂涨 | `pm2 logs <name> --err`；连续 10 次拉不起会停手（`max_restarts`） |
| console 起来但页面 502/连不上 | `.env` 的 `NITRO_HOST` / `NITRO_PORT`；`pm2 describe colab-console` 看 node_args 有没有生效 |
| 页面报 `RUNNER_UNAVAILABLE` | runner 是否在跑；`web/.env` 的 `NUXT_RUNNER_TOKEN` 与 Runner 的 `COLAB_RUNNER_TOKEN` 是否一致 |
| 改了代码没生效 | 忘了 `npm run build`（见 §2） |
| 停服务后 python 还在 | 确认 `start-runner.mjs` 里的信号转发那段还在；`pgrep -af colab_runner` |
| 磁盘被日志吃满 | §4.3 的 pm2-logrotate 没装 |
