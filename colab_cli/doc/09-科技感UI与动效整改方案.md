# 09 科技感 UI 与动效整改方案

> 2026-09-24，基于 `web/` 当前源码审查。本文是实施方案，尚未修改界面，也未进行登录后的浏览器视觉验收。既有的 [07-UI风格优化计划](./07-UI风格优化计划.md) 已完成 token、交互态、响应式及少量动效；本方案从其现状继续升级。

## 1. 目标与设计方向

将产品从「朴素的管理后台」升级为「专业的计算任务指挥台」：第一眼有清晰的科技气质，第二眼能迅速识别正在运行、需要处理和已完成的任务，长时间使用仍然安静、易读。

系统原生支持**双皮肤方案（白天 / 夜间）**：
- **夜间皮肤（默认）**：采用 **曜石深蓝 + 电青光迹** 作为主视觉，深蓝用于导航、背景和监控工作区；高亮电青标识当前操作与实时数据；琥珀色专属 `recoverable` 持续计费风险；红色专属销毁、失败与孤儿告警。科技感来自信息布局、克制的发光层次与数据变化。
- **白天皮肤**：采用 **晨曦极光 + 现代工程浅色** 作为高光与明亮场景支持，经典 Arco 极光蓝高对比操作、舒缓现代灰底（防眩目）、高辨识度文字与面板层级，并保持日志面板的真实终端黑。
- 用户可在顶部导航与登录页自由切换皮肤，选择即时生效并持久化到 `localStorage`，兼顾系统 `prefers-color-scheme` 自适应。

## 2. 当前界面审查

| 现状证据 | 体验问题 | 改造机会 |
| :--- | :--- | :--- |
| `web/assets/css/main.css` 是浅灰页底、白色卡片、Arco 蓝；卡片主要为同一层级的边框与阴影 | 视觉重心平均，缺少大气的空间感 | 重建背景、面板、数据强调和层次 token；用「主舞台 + 次级面板」区分信息权重 |
| `web/app.vue` 是一行横向导航，只有当前项底边线；Toast 已有进出场 | 品牌识别与页面切换仪式感较弱 | 桌面端导航加入品牌区、系统状态与活跃指示；窄屏保留当前可横滑导航 |
| `web/pages/index.vue` 用四张纵向卡片呈现用户、会话、运行中、可重取 | 首屏缺少关键指标概览；运行任务与风险需要逐段阅读 | 顶部总览数字、运行任务主舞台、右侧会话健康及可重取告警 |
| `web/pages/tasks/[id].vue` 已有摘要、`TaskTimeline`、`MetricsChart`、`LogViewer` | 实时计算过程已有数据，却在视觉上像静态表单 | 阶段进度、曲线更新、连接状态、日志新行成为动效重点 |
| `web/pages/tasks/new.vue` 是较长的单列表单，含工作流参数、图片、会话、加速器与草稿状态 | 选择过程有信息，但提交前缺少清晰的决策摘要 | 桌面端「配置区 + 提交摘要」；动态字段展开、草稿保存反馈 |
| `web/pages/tasks/index.vue` 等列表页主要为表格，窄屏通过横向滚动承载 | 数据密度合理，但检索和状态定位不够突出 | 增加状态筛选视觉权重、行级状态指示与稳定的加载/空态 |
| 全站可见动效主要是 Toast 和时间线呼吸点；`web/assets/css/main.css` 已有 `prefers-reduced-motion` | 状态切换通常是硬更新；仍有充足的动效空间 | 按“导航、反馈、实时数据、状态转换”建立统一动效语言 |

以上是源码审查结论。视觉观感、窄屏实际效果、色彩对比与动画流畅度，需在可登录环境中通过截图和录屏验证。

## 3. 视觉系统

### 3.1 双皮肤色彩体系与 Token 对照

系统通过 `web/assets/css/main.css` 的语义 CSS Token 统一承载双皮肤，组件与页面内统一引用 `var(--c-*)` 和 `var(--sh-*)`，不硬编码色值。

| 语义 Token | 夜间模式（默认 · 曜石深蓝） | 白天模式（晨曦极光 · 现代浅色） | 用途与 WCAG 说明 |
| :--- | :--- | :--- | :--- |
| `--c-bg` | `#080F1D`（深邃暗夜） | `#F2F5F9`（现代舒缓灰） | 页面底层画布，带有细微低透明度工程网格与轻光晕 |
| `--c-surface` | `#101C30` | `#FFFFFF` | 主面板、卡片容器底色 |
| `--c-surface-sub` | `#16243A` | `#F8FAFC` | 工具栏、表格头、次级卡片底色 |
| `--c-surface-hover` | `#1C2E4A` | `#EDF2F7` | 列表行 hover、交互 hover 背景 |
| `--c-border` | `#29405B` | `#D8E0EA` | 面板外边框、列表分隔线 |
| `--c-border-strong` | `#3D5C80` | `#B9C6D6` | 输入框边框、次级按钮边框 |
| `--c-divider` | `#1C2E47` | `#E8EEF5` | 表格行间极浅分割线 |
| `--c-text` | `#ECF4FF`（浅蓝白） | `#182230`（深青黑） | 主文字、标题、高亮指标（对比度 > 10:1，超 WCAG AAA） |
| `--c-text-sub` | `#A9BED4` | `#475467` | 辅助文字、字段标签（对比度 > 5:1） |
| `--c-text-weak` | `#728CA8` | `#667085` | 次级时间、元数据（对比度 > 4.5:1） |
| `--c-text-invert` | `#080F1D` | `#FFFFFF` | 主按钮/危险按钮高亮底上的反色字 |
| `--c-brand` | `#39D8E8`（电青） | `#165DFF`（极光 Arco 蓝） | 品牌高亮、选中项、主操作按钮 |
| `--c-brand-bg` | `rgb(57 216 232 / 12%)` | `rgb(22 93 255 / 8%)` | 品牌弱背景、图表填充面 |
| `--c-running` | `#39D8E8` | `#165DFF` | 运行中任务状态 |
| `--c-success` | `#43D7A0`（翡翠青绿） | `#059669`（深翡翠绿） | 成功终态、在线健康指标（对比度 > 4.5:1） |
| `--c-warn` | `#FFBF69`（琥珀金） | `#D97706`（深琥珀金） | `recoverable` 持续计费告警（醒目高亮） |
| `--c-danger` | `#FF7081`（珊瑚红） | `#DC2626`（警示正红） | 失败、销毁 VM、孤儿会话告警 |
| `--c-log-bg` | `#060B14` | `#0D131F` | 日志终端保持专业黑底（保证长日志阅读专注度） |

#### 皮肤切换与持久化机制
1. **状态驱动**：Pinia `uiStore.theme`（`'dark' | 'light'`），全局方法 `toggleTheme()` / `setTheme()`。
2. **免闪烁同步（FOUC 保护）**：Nuxt Head 注入微型同步脚本，页面解析时立刻读取 `localStorage('colab_theme')`（无存储时自适应系统 `prefers-color-scheme`），并在 `document.documentElement` 设置 `data-theme` 属性。
3. **视觉切换入口**：
   - 全局顶部导航右侧显式展示 `☀️ 白天` / `🌙 夜间` 切换按钮（移动端自适应收纳）。
   - 登录页右上角提供常驻皮肤切换入口，未登录时亦可按需调节。
4. **平滑过渡**：全站 `body`、按钮、面板均具备 `var(--t-base)` 平滑背景与字体色彩过渡，避免换肤生硬闪烁。

### 3.2 页面骨架

桌面端建议 1280–1440px 内容上限、24–32px 页面留白。主要操作固定在标题右侧，内容依“状态概览 → 当前工作 → 历史详情”排列。登录页和空态可用更大的留白，其余页保持数据密度。

总览页建议布局：

```text
┌ 品牌 / 主导航 ─────────────────── 系统连接状态 / 用户 ┐
│ 标题、说明                         提交任务           │
│ 在线会话     运行任务     可重取风险     今日完成       │
│ 运行任务主舞台（阶段、时长、会话、动作） │ 会话健康      │
│                                      │ 风险待办      │
└ 最近任务 / 快捷入口 ────────────────────────────────┘
```

“今日完成”需确认现有数据能准确计算后再展示；无法可靠计算时改用现有的“表内会话数”等事实指标。不要为视觉效果制造虚假的实时数字或进度百分比。

## 4. 动效规范

动效应让用户看清**发生了什么、从哪里来、下一步去哪**。下面的时长是实施起点，样稿和真机试用后可微调。

| 场景 | 效果与触发 | 时长 / 约束 | 落点 |
| :--- | :--- | :--- | :--- |
| 页面切换 | 主内容 8–12px 位移 + 淡入；导航活跃指示平移 | 180–260ms；返回与前进方向一致，避免整页闪白 | `app.vue` / 页面过渡 |
| 首屏出现 | 标题、指标、主任务区分层入场 | 每层相差 40–60ms，总入场 ≤ 500ms；只在首次进入时播放 | `pages/index.vue` |
| 按钮与输入 | hover 亮度/描边变化，按下轻微缩放；输入焦点柔和描边 | 120–180ms；危险按钮保持危险色；键盘焦点明确可见 | `main.css` 与各页面 |
| 列表更新 | 新任务淡入、状态徽章颜色平滑变更；移除时淡出 | 180–240ms；只动画可见行，不对高频刷新重排整表 | `tasks/index.vue`、`sessions/index.vue` |
| 任务阶段 | 新阶段节点点亮，连接线向下推进，阶段内容展开 | 240–360ms；**仅在阶段事件发生时**播放一次；运行中呼吸点可保留 | `TaskTimeline.vue` |
| 指标曲线 | 新采样点的线段/最新读数平滑衔接，鼠标或触控聚焦显示同一时刻数据 | 数据每 2 秒更新一次；不逐帧重算整条 150 点曲线 | `MetricsChart.vue` |
| 实时日志 | 仅最新行短暂描边或背景淡化；滚动跟随状态切换有即时反馈 | ≤ 500ms；不对虚拟列表每行做入场动画 | `LogViewer.vue` |
| 上传与提交 | 拖入时边框吸附、预览淡入；提交后按钮进入等待态、成功/失败给予明确结果 | 200–300ms；上传进度只在有真实进度数据时显示 | `FrameDropZone.vue`、`tasks/new.vue` |
| 告警与 Toast | 告警从原位置展开；Toast 保持现有右侧进入、堆叠位移 | 200–300ms；孤儿告警长期常驻，不循环闪烁 | `SessionOrphanBanner.vue`、`app.vue` |

实现优先用 Vue 内置 `<Transition>` / `<TransitionGroup>` 与 CSS。Vue 官方说明二者适合元素进出和列表增删移动：[Transition](https://vuejs.org/guide/built-ins/transition)、[TransitionGroup](https://vuejs.org/guide/built-ins/transition-group)。页面/组件继续遵循 [04 §1](./04-前端规范.md) 的 `container_...` 类名规则，过渡类通过 Vue 的显式 class prop 指定。不要仅为动效引入完整动画库。

性能边界：优先动画 `transform` 与 `opacity`；阴影、滤镜和大面积模糊只用于静态状态或小范围控件。高频 SSE 到达时不得启动每行或每采样点的多重动画；隐藏标签页停止装饰性循环效果。依据：[web.dev 的高性能动画指南](https://web.dev/articles/animations-guide)。现有 `prefers-reduced-motion` 规则继续生效，新增的 JS 动画也必须主动尊重该偏好；状态变化仍用文字和数值表达，不能只靠运动。规范依据：[WCAG 2.2 动画与状态消息](https://www.w3.org/TR/WCAG22/#animation-from-interactions)。

## 6. 实施顺序与交付物

| 阶段 | 工作 | 可评审产物 | 通过标准 |
| :--- | :--- | :--- | :--- |
| A · 样稿 | 完成总览、任务详情、登录的桌面与移动静态稿；确定深色配色及动效分镜 | 样稿、色板、关键状态截图 | 可重取/孤儿/失败优先级明确；文字对比度合格 |
| B · 基础层 | 更新 token、导航、全局背景、面板与按钮；加入页面过渡 | 可运行的全局骨架 | 所有页面无明显色彩断层，旧浅色硬编码清零 |
| C · 实时核心 | 改总览、任务详情与三个监控组件 | 运行中、断线重连、终态录屏 | 状态变化正确，日志跟随与虚拟滚动不受影响 |
| D · 操作页 | 改任务表单、列表、会话及上传区 | 完整操作路径录屏 | 提交、停止、下载、上传反馈清晰；权限和校验未回退 |
| E · 收尾 | 改历史、工作流、用户页；响应式、低动效、性能及可访问性验收 | 各尺寸截图与验收记录 | 下节清单全部通过 |

建议以 A、B、C 作为首个有明显感知的交付批次。先做样稿能尽早确认“科技感”的审美方向，避免全站完成后大范围返工。估算：A 1–2 天，B 1–2 天，C 2–3 天，D 2–3 天，E 1–2 天；总计约 7–12 个开发日，依视觉稿修改次数和真实数据环境而变。

## 7. 验收标准

- 视觉：在 375、768、1440px 三档完成总览、任务详情、提交任务、会话页截图；无页面级横向溢出，状态色与动作色一致；登录与空态不出现布局跳动。
- 功能：登录、提交、取消/销毁、重取下载、上传首尾帧、会话对账与角色权限逐项回归；动画不能掩盖按钮禁用、错误提示或真实任务状态。
- 动效：录屏逐项检查第 4 节；连续 SSE 期间无明显掉帧；切换页面、返回、后台标签页恢复后状态仍正确。浏览器不支持增强动画时正常显示内容。
- 可访问性：键盘全程可操作且焦点可见；状态消息可由辅助技术获知；低动效模式关闭位移和循环装饰；普通文本、关键控件边界满足对应 WCAG 对比度要求。
- 工程：`npm run lint`、`npm test`、`npm run build` 通过。对实时核心额外检查性能录制；不能因动效改坏 `LogViewer` 的虚拟滚动或 `taskStream` 的定长缓冲。

## 8. 风险与取舍

1. **深色主题可能降低长表格可读性。** 表格采用低饱和度面板与清楚的行分隔；评审时同时展示长列表与错误态，不只看总览首屏。
2. **过量动效可能干扰监控。** 循环动画只保留少数实时指示；任务到达终态即停止。持续计费风险优先靠文字、位置和颜色表达。
3. **实时数据可能带来渲染开销。** 曲线只处理新增采样；日志保持现有虚拟滚动。必要时降低装饰性背景与阴影复杂度。
4. **旧规范与新视觉存在边界。** [07](./07-UI风格优化计划.md) 的 token 和响应式基础可复用；本方案允许为新布局调整模板结构，但继续遵循 [04](./04-前端规范.md) 的命名、权限、术语和可访问性约定。
